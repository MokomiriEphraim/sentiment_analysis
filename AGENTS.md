# AGENTS.md

## Architecture

- Single-package Google AI Studio app ("Cloud Sentiment"): React 19 + Vite 8 + Tailwind 4 SPA served by one Express server, `server.ts`. No monorepo, no lockfile (fresh `npm install` resolves latest matching semver).
- `server.ts` is the real entrypoint for both modes: dev = Express + Vite in middleware mode (HMR works via `vite.middlewares`); prod = Express serving `dist/`. Don't run `vite` or `vite preview` directly — `vite preview` has no API routes.
- Sentiment analysis has **two tiers**: (1) the **primary engine is the Python VADER sidecar** — Workbench overall score, sentence scores, word scores, emoji scores (`src/nlp/vaderClient.ts`, 300ms debounce, stale-guard `vaderSeqRef`), **and the Live Comments pull** (single batch call `/api/py-batch`, consumer `LiveStream.tsx`); the local rules engine (`src/nlp/sentimentEngine.ts`, lexicon in `src/nlp/lexicon.ts`) renders instantly first and **stays as fallback when the sidecar is down** — badges in the Workbench scorecard and Live Comments header show `VADER model` / `connecting…` / `VADER offline — fallback`. Qualitative extras (emotions/tones/sarcasm/aspects/subjectivity/NPS, used by the report) remain local rules. (2) `onResultChange` lifts the Workbench result into `App.tsx` so the Full Report shows the exact numbers on screen. **Tab history (user request 2026-10):** a **Dashboard tab existed and was deleted outright** — it went through a "same as Workbench" phase, an overview-only phase (stat cards + Score Trend LineChart + pie + sorted results), and an emerald-banner restyle, all at the user's direction; final state = `src/components/Dashboard.tsx` removed, `NavTab` = `'workbench' | 'stream'`, nav has Workbench + Live Comments only. **Don't rebuild it without asking.** Workbench = ONE text, deep dive (word inspector, sentences, sarcasm, emoji panel, and a Sentiment Split pie under the emoji panel fed by `result.posScore/neuScore/negScore`). Emoji panel lives in Workbench: `vader` prop = model scores, `emotionKey` prop shows a "Your tone suggests" emoji row when the text has no emoji characters (passes `result.emotions.dominantKey`). **Voice input (2026-10, rewritten):** Workbench `voice` sub-view → `src/components/VoiceStudio.tsx` — language picker for all 11 SA languages (`LANGS`: browser `*-ZA` tag + Whisper ISO code). Two paths split by `liveSttSupported`: Chrome/Edge = live Web Speech transcription (free, `recognition.lang` = picked language, auto-restarts on Chrome's silence-`onend` while `activeRef` is true, finalized+interim transcript kept in `finalRef`/`displayRef` so `resultIndex` updates never wipe earlier speech) → "Stop & Add to Text" appends to the editor; Firefox/Safari = MediaRecorder → `POST /api/transcribe`. 2-min auto-stop cap, mic released on unmount, instant live badge is LOCAL RULES ONLY (labelled "Instant") — the real VADER+AI score comes from the editor pipeline after the transcript lands. **Branding rule (user request): the words OpenAI / gpt-4o / GPT must never appear in UI components** — the AI Deep Analysis modal shows "Source: cloud AI" (it still calls the OpenAI endpoint under the hood); the old Compare Models card was deleted outright (2026-10, user request). UI tabs are declared in `src/App.tsx` + `src/components/Header.tsx` (`NavTab` union); widgets are wired inside `src/components/Workbench.tsx`. Removed as cruft (2026-10): Aspect Constellation, Top Valence Drivers, Plutchik Wheel, Valence Morph Synthesizer, Churn card — their nlp modules (`plutchik.ts`, `churnRiskEngine.ts`, `valenceSynthesizer.ts`) were deleted too; don't resurrect them. **Health auto-recovery (2026-10):** `GET /api/py-health` is polled every 15s (`startVaderHealthPolling()` from `App.tsx`), and every real VADER fetch also updates the shared `vaderHealth` (`src/nlp/vaderClient.ts`, `subscribeVaderHealth`); when health reports `up` while a tab badge sits in fallback, that tab re-runs its scoring — Workbench bumps a `vaderRetry` state (effect dep) to re-fire the debounce, LiveStream re-scores the whole `pullRef` (full pull, revealed + queued) and patches items by id — so the badge and scores heal **without the user typing**. **Visual tab distinction (user request 2026-10, "they look identical"):** Workbench header = plain compact one-line toolbar (text-base title, inline subtitle, zinc chrome) — the Dashboard's competing emerald banner died with the tab.
- No demo/mock data ships: `src/nlp/presets.ts` (sample corpora) was deleted. `src/components/LiveStream.tsx` (tab label "Live Comments") is now a **real scraper UI**: URL input → `POST /api/scrape-comments` (Firecrawl or Apify) → the **whole pull is scored with VADER before the reveal starts** (`fetchVaderBatch` patched into items up-front, `engineState` idle→connecting→vader/fallback — so every streamed comment lands with its final model score; local rules only when sidecar down) → comments are **revealed progressively** (one every 3s, `REVEAL_MS` const, timer in `revealTimerRef` + `stopReveal`, progress UI is a **spinner-only** green box per user request — pie/counts/spike-alert (checks last 5) update per tick; `SentimentPie` recharts animation is ON, 700ms ease-out, don't disable it). The old post-reveal batch effect (`batchKey`/`vaderSeqRef`/`pendingTextsRef`) was removed — don't reintroduce it; emotion/tone meta row per comment only renders when non-Neutral (or sarcasm). Layout: comments table (`lg:col-span-2`) + Comment Breakdown pie side by side; the old sparkline card ("Sentiment (last 20 comments)") was **deleted** (user request) along with the fake play/pause/speed controls — don't add simulated feed ticks or the sparkline back. **CSV export (2026-10):** `downloadCsv()` in the filter bar exports ALL loaded `streamItems` (Source/Time/Author/Comment/Score/Label/Emotion/Tone/Sarcastic), UTF-8 BOM for Excel + quote-escaping — respects no filters (full pull). The per-row ↗ arrow calls `onSendToWorkbench` → `App.handleSendToWorkbench` sets `workbenchText` + `setActiveTab('workbench')` (already navigates; Workbench re-mounts with the prop as editor text — verified working). The Workbench text is lifted state (`workbenchText` in `App.tsx`): it feeds both the editor and the Executive Report — keep that single source of truth.
- `src/nlp/customRules.ts` still *loads* custom words + engine settings from browser `localStorage` (defaults if absent), but the old Lexicon Rules editor UI was removed — nothing writes to it anymore. There is no server-side state.
- **MongoDB persistence (optional, added 2026-10):** env keys `MONGO_URI` + `MONGO_DB` (user's live db name: `CloudSentiment`); `mongodb` npm driver in `server.ts`, **lazy + degrade-gracefully** like the sidecar — `getMongoDb()` connects on first use (3s serverSelection timeout, 30s cooldown after failure), no URI → feature silently off. Three collections, created on first connect with indexes: `devices` (_id = client-generated UUID from `localStorage` key `cs_device_id`, metadata: userAgent/platform/language/screen/viewport/timezone/firstSeen/lastSeen/pullCount), `pulls` (one per successful scrape: deviceId/url/platform/provider/commentCount/createdAt), `comments` (every scraped comment: pullId + deviceId links). `recordPull()` in `server.ts` upserts the device, inserts the pull, inserts all comments, and **returns the pull id string (null on failure)** — responses include `pullId` + `saved`; **never fails the scrape**, and LiveStream appends "· saved to database" to its end-of-reveal info line when true. Client sends `{deviceId, device}` with every scrape (`src/lib/device.ts` — `getDeviceId()`/`getDeviceMeta()`). `GET /api/db-health` = liveness probe (`{configured, available, dbName}`). **Pull history (read-back, 2026-10):** device-scoped routes `GET /api/pulls?deviceId=` (list, newest first, cap 50), `GET /api/pull-comments?pullId=&deviceId=` (ownership-checked via `pulls.findOne({_id, deviceId})` → 404 otherwise, comments capped 200), `DELETE /api/pulls/:id?deviceId=` (deletes pull + its comments, same ownership check). `DEVICE_ID_RE = /^[\w-]{8,64}$/` shared by all routes. Consumer: LiveStream's **Pull history** card (auto-loads on mount, hidden when Mongo off/empty) — **View** loads a pull's comments into the table and re-scores them with the shared `scoreBatch()` (VADER + AI-0.00 pass, same as live pulls) + refresh after each scrape/delete/back.
- Optional Python sidecar (`python/main.py`, FastAPI + VADER): Express proxies to it; it degrades gracefully (endpoints return `available: false`, UI shows "unreachable" and keeps local-rule numbers, badge → `VADER offline — fallback`).

### Backend endpoints (all in `server.ts`)

- `POST /api/neural-deep-sense` — OpenAI chat completions with strict `json_schema` output (model via `OPENAI_MODEL`, default `gpt-4o-mini`); client: `src/components/NeuralSenseModal.tsx` (renders `res.source` dynamically).
- `POST /api/transcribe` — voice input cloud path: `{audioBase64, mimeType, language}` (base64 audio ≤9MB, `language` = ISO-639-1 like `zu`/`af`) → `whisper-1` (`OPENAI_TRANSCRIBE_MODEL` override) → `{available, text}`. Used ONLY by browsers without live Web Speech (Firefox/Safari — `VoiceStudio` picks the path via `liveSttSupported`); Chrome/Edge transcribe free in-browser. Always 200 with `available:false` on failure (no key, timeout, empty audio → 400).
- `POST /api/assistant` — floating help assistant (bottom-right widget, `src/components/HelpAssistant.tsx`, rendered in `App.tsx` on all tabs): `{messages:[{role,content}], context?}` → trimmed to last 14 × 3000 chars → `OPENAI_MODEL` with a curated app-knowledge system prompt (tabs, two-tier engine, SA-language pass, voice, ports 3000 vs 8000, .env keys, common fixes). `context` = client-built snapshot of the on-screen analysis (tab + scores / pull stats) so the assistant can answer "how did my analysis do?" and know a report exists. **Email intent routing:** if the model judges the user asked to email the report to an address, it replies with ONLY `{"action":"send_report","email":"…"}` (any SA language works) → server returns `{intent, email}` → client packages the report (`src/lib/reportEmail.ts` — `buildWorkbenchReport(result)` / `buildLiveReport(live)` produce subject + styled inline-CSS HTML + text; data comes from App's lifted `workbenchText`/`currentReportResult` and `liveReport` state fed by `LiveStream`'s `onReportData` prop) → `POST /api/send-report` → confirmation bubble. **Deterministic fast path (client, beats model flakiness):** if the message contains ≥1 email (`EMAIL_GLOBAL_RE`, trailing punctuation stripped, cap 5) AND a send verb (`SEND_VERB_RE` = English send/mail/email/deliver + thumela/romela/rumela/rhumela/stuur/posta) and is NOT a question (`looksLikeQuestion` guard) → `deliverReport()` runs directly, no model roundtrip; model intent remains the fallback for everything else. Multi-recipient: `to` accepts string or string[] (cap 5). Otherwise the model's normal text reply is shown. Enforces "no provider brand names" in the prompt (branding rule); no key → `available:false` with a setup hint. Widget: welcome bubble seeded, plain-text bubbles (`whitespace-pre-wrap`, no markdown), Enter to send, z-40 (no backdrop/blur — removed at user request).
- `POST /api/send-report` — email delivery via **Resend** (`resend` npm pkg). Env: `RESEND_API` (user's key name; `RESEND_API_KEY` also accepted) + `RESEND_FROM` (user's verified domain `reports@titans-cogni.com`; default `onboarding@resend.dev` = sandbox, only delivers to the account's own email). Body `{to, subject, html, text}` — `to` = string or string[] (cap 5, each validated), html ≤700KB. Resend `error` object surfaces verbatim in the assistant chat (e.g. sandbox restriction). Live-tested: intent extraction → styled report HTML → `available:true` id, incl. dual-recipient send.
- `GET /api/py-health` — sidecar liveness probe (1.5s timeout, **any** HTTP response from `PYTHON_URL` counts as up); polled every 15s by the client for badge auto-recovery.
- `GET /api/db-health` — MongoDB liveness probe (`{configured, available, dbName}`); connects lazily via `getMongoDb()`.
- `GET /api/pulls` / `GET /api/pull-comments` / `DELETE /api/pulls/:id` — device-scoped pull history (MongoDB): list newest-first cap 50; fetch one pull's comments (ownership-checked → 404 to other devices, cap 200); delete pull + comments (same check). All require the client's `deviceId` (`DEVICE_ID_RE`); no Mongo → `{available:false}`.
- `POST /api/py-analyze` — proxies to the Python sidecar at `PYTHON_URL` (default `http://127.0.0.1:8000`, 4s timeout); sidecar down → `available: false`.
- `POST /api/py-sentences` / `POST /api/py-words` — proxy sidecar `/sentences` + `/words` (per-sentence / per-word VADER scores, added2026-10). **The sidecar must be restarted after editing `python/main.py`** or these404 → Workbench falls back to local rules.
- `POST /api/scrape-comments` — comment scraper for the Live Comments tab: takes `{url, deviceId?, device?}` (deviceId/device = browser identity+metadata, persisted with the pull), detects platform. Success responses now include `pullId` (string, the Mongo id — null when Mongo is off) alongside `saved`. **TikTok / Instagram / YouTube → Apify** (shared `runApifyActor()` + `mapComments()` helpers; `APIFY_API_KEY` in `.env` → otherwise a setup message; 402 → out-of-credits), **everything else (Facebook / X / Reddit) → Firecrawl**. (a) TikTok: actor `GdWCkxBtKWOsKjdch` (clockworks/tiktok-scraper), `{postURLs, commentsPerPost:50, topLevelCommentsPerPost:50}` (175s timeout), then **fetches the video item's `commentsDatasetUrl`** (separate dataset, signed URL, no token needed) for the actual comments (`text`, `uniqueId`); `errorCode` map (`POST_NOT_FOUND_OR_PRIVATE` etc.) → friendly messages. (b) Instagram: actor `shu8hvrXbJbY3Eb9W` (apify/instagram-scraper) with `{directUrls, resultsType:"comments", resultsLimit:50}` → items `{text, ownerUsername}`; **free Apify plans cap ~15 comments/post**. (c) YouTube: actor `p7UMdpQnjKmmpR21D` (streamers/youtube-comments-scraper) with `{startUrls:[{url}], maxComments:50}` → items `{comment, author}`; error items map `NO_COMMENTS`/`VIDEO_UNAVAILABLE`/`AGE_RESTRICTED` → friendly messages. **Do NOT swap YouTube to `streamers/youtube-scraper` (h7sDV53CddomktSi5) — live-tested, its `comments` field is always null;** Firecrawl's old YouTube branch returned 0 comments (dead path for YT now). (d) Firecrawl branch: Firecrawl **v2** `POST https://api.firecrawl.dev/v2/scrape` with `formats:[{type:"json", prompt, schema}]` + wait/scroll actions (comments lazy-load below the fold) + `maxAge:0`, 90s timeout, caps 100 comments; needs `FIRECRAWL_API_KEY`; 402/credit errors mapped to a clear message. Extracted JSON read from `data.json` (fallback `data.extract`). **Live-tested 2026-10 through our API: YT → 50 comments, IG → 15, TikTok → 50.**
- `POST /api/py-batch` — proxy sidecar `/analyze-batch` (`{texts: string[]}` → `[{compound,label,scores}]`, 6s timeout); consumer: `LiveStream.tsx` scores the whole pull up-front (before the reveal starts) and re-scores it on health recovery. **VADER is English-only:** after the py-batch, LiveStream takes every item whose `compound === 0` (almost always isiZulu/Sesotho/Afrikaans/Xitsonga/slang) and batches them into ONE `POST /api/ai-scores` call (`{texts}` cap 60, gpt-4o-mini, 25s timeout, strict json_schema `{scores:[{compound,label}]}` in input order, prompt lists all 11 SA languages + township slang); the returned scores patch those items in place *before* the reveal starts. When the key is missing or the call fails the endpoint returns `available:false` and the neutral scores are kept — never blocks the scrape. The end-of-reveal info line appends `· N scored with cloud AI`. Workbench does the same: when the sidecar overall is exactly 0, it fires one `fetchAiScores([text])` call and overrides `compound`/`label` (pos/neu/neg bars stay as VADER left them). Client helper: `fetchAiScores()` in `src/nlp/vaderClient.ts`.
- Client consumer (formerly `src/components/ModelConsensusCard.tsx`) — **card deleted** (user request, 2026-10): "Compare Models" / "Run Comparison" / "AI Model" rows removed from the Workbench. Its two endpoints `/api/openai-sentiment` and `/api/hf-sentiment` were **deleted from `server.ts` too** (2026-10 cleanup: unused by any UI + HF inference is 402-paid). ## Commands

- `npm run dev` — dev server (`tsx server.ts`, port `PORT` or 3000).
- `npm run lint` — this is just `tsc --noEmit`. It is the only automated check: no ESLint, no Prettier, no tests, no test framework. Run it after every edit; don't add test tooling unless asked.
- `npm run build` — `vite build` → `dist/`. Warning about >500 kB chunk is pre-existing/expected (recharts added to it).
- `npm run sidecar` — Python VADER sidecar on port 8000. One-time setup first: `python3 -m venv .venv && .venv/bin/pip install -r python/requirements.txt`, then run uvicorn from that venv (`cd python && <venv>/bin/uvicorn main:app --port 8000`). Scripts assume a unix shell (like the existing `clean` script).
- `npm start` — `node server.ts`, but it does **not** imply production: mode is chosen by `NODE_ENV !== 'production'`, and prod needs `npm run build` first to have `dist/`.

## Gotchas

- Env loading: server uses `dotenv.config()` → reads **`.env`**, not `.env.local`. `.env*` is gitignored except `.env.example`. Missing keys are all supported states: `OPENAI_API_KEY` and the Python sidecar are each optional; endpoints return `available: false` and the UI falls back to the local deterministic engine. `metadata.json` still declares `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API` — stale AI Studio platform metadata, left as-is (do not treat it as the provider).
- `npm install` used to fail with ERESOLVE (stale `esbuild@^0.25.0` devDep vs vite 8 peer range) — the unused esbuild devDep has been removed; if install conflicts reappear, check peer ranges before reaching for `--legacy-peer-deps`.
- Do not touch the `hmr`/`watch` settings in `vite.config.ts`: AI Studio injects `DISABLE_HMR=true` to disable file watching during agent edits; the comments there are deliberate.
- Model id for the neural endpoint defaults to `gpt-4o-mini` (`OPENAI_MODEL` override in `.env`) — the old Gemini client SDK (`@google/genai`) has been removed from the project.
- The `@/` path alias (vite.config + tsconfig) maps to the repo root but is unused; all existing imports are relative — keep it that way.
- Tailwind v4: no `tailwind.config` file; everything comes from `@import "tailwindcss"` in `src/index.css`.
- Charts use `recharts` (v3): `src/components/SentimentPie.tsx` is the shared pie (pos/neu/neg, colors emerald/zinc/rose) used by Workbench (this text's split) and Live Comments (Comment Breakdown); the deleted Dashboard also used it.
- `npm run clean` removes `dist` and `server.js`; nothing currently emits `server.js` (leftover from an older build flow).
